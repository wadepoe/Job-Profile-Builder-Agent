# Product Requirements Document (PRD)

**Title:** Job Profile Builder Agent
**Date:** 2026-11-12
**Owner:** HR / Talent Transformation Team
**Solution Category:** AI Agent

---

## Product Purpose & Value Proposition

**Elevator Pitch:**
HR teams spend over 30 minutes manually entering every job description into SAP SuccessFactors Job Profile Builder. This agent eliminates that burden — accepting data in any format, filling gaps automatically from the client's own job architecture, and delivering a completed, template-compliant profile in under 2 minutes.

**Business Need:**
SAP SuccessFactors Job Profile Builder requires each profile to be manually entered section-by-section into template-governed shells, or loaded from existing profiles via CSV exports. With hundreds of thousands of profiles to create — and new ones urgently needed to support active recruiting — the manual process is a critical bottleneck. Profiles are a prerequisite for attaching to job requisitions and applications; delays directly impact time-to-hire.

**Expected Value:**
- Per-profile creation time reduced from ~30 minutes to under 2 minutes
- Initial large-scale job architecture migration completed as fast as possible at go-live
- 100% of profiles generated by the agent and reviewed by a human — zero manual re-entry

**Product Objectives (Prioritized):**
1. Eliminate manual job profile data entry through AI-driven content generation from any source input
2. Support both single interactive profile creation and unlimited batch processing for migrations
3. Deliver completed profiles to SuccessFactors via API, CSV bulk upload, or formatted document — at the user's choice
4. Integrate with the client's own SuccessFactors job architecture to ensure structural consistency and reduce clarifying questions

## User Profiles & Personas

Alex is a 34-year-old talent acquisition specialist working in a large enterprise HR team. On any given day, Alex needs to create or update several job profiles so that recruiters can attach them to open requisitions and start sourcing candidates. Jordan's pain is scale — the manual process is simply not viable for the volume required, and quality is inconsistent across contributors. Jordan needs a way to feed in a structured list of roles and get complete, consistent profiles out, ready for review and import.

**Key frustrations:** Volume, consistency across contributors, deadline pressure on migration projects.

## Product Principles

1. **Accept whatever the user provides:** The agent never refuses to start because the input is imperfect. It works with what it has and asks targeted questions only for what it genuinely cannot infer.
2. **Human always has final say:** The agent proposes; the human approves. No profile is written to SuccessFactors without explicit user confirmation.
3. **Structure from the source of truth:** The agent always reads the client's own job architecture and templates from SuccessFactors before generating content — not generic assumptions.
4. **Output flexibility over lock-in:** Three output modes (API write, CSV, document) ensure the agent is useful regardless of the client's SuccessFactors configuration or permission level.
5. **Batch is a first-class citizen:** Scale is a core use case, not an afterthought. Batch processing must be as robust and reliable as single-profile creation.

## Business Context

**Current State:**
Clients manage two painful methods for job profile creation in SAP SuccessFactors Job Profile Builder. Method 1: manually enter all job description content into an empty template shell, section by section. Method 2: export sections of existing profiles into CSV files, edit them, and re-import. Both methods average over 30 minutes per profile. For an enterprise with hundreds of thousands of profiles, this represents an enormous and recurring labor cost. The problem is most acute during implementation migrations and when urgent recruiting needs arise.

**Strategic Alignment:**
Automating job profile creation directly supports a faster time-to-hire, reduces HR operational costs, and enables clients to realise the full value of their SuccessFactors investment. The agent also supports the talent-driven business model where a well-maintained job architecture underpins recruiting, performance, succession, and career development.

## Goals and Non-Goals

### Goals (In Scope)

- AI-driven generation of complete, template-compliant job profiles from any source format
- Single interactive profile creation with conversational gap-filling
- Unlimited batch profile generation from a file or role list
- Integration with SuccessFactors job architecture, templates, positions, skills, and job requisition APIs
- Three output modes: direct API write to SuccessFactors, CSV bulk-upload export, and formatted document draft

## Requirements

### Must-Have Requirements

**R1: Flexible Source Data Intake**
- **Problem to Solve:** Users have source data in many forms and cannot be expected to reformat it before the agent will help.
- **User Story:** As an HR specialist, I need to provide source data in any format — paste, file upload, clone instruction, or verbal description — so that I can start the profile creation process without pre-processing.
- **Acceptance Criteria:**
  - Given a user pastes unstructured text, when the agent receives it, then it extracts all identifiable job profile fields automatically.
  - Given a user uploads a Word or PDF document, when the agent receives it, then it parses the file and extracts job profile content.
  - Given a user instructs the agent to clone an existing profile by name or code, when the agent receives the instruction, then it retrieves the existing profile from SuccessFactors and uses it as the base.
  - Given a user describes a role verbally, when the conversation ends, then the agent has captured sufficient information to begin profile generation.
- **Maps to Objective:** 1
- **Priority Rank:** 1

**R2: Gap Resolution via SuccessFactors Job Architecture**
- **Problem to Solve:** Source data rarely contains every required field. The agent must resolve gaps intelligently rather than leaving sections empty or asking the user to supply everything manually.
- **User Story:** As an HR specialist, I need the agent to look up my organisation's job architecture and templates in SuccessFactors to fill gaps, so that I only answer questions the system cannot answer on its own.
- **Acceptance Criteria:**
  - Given a source input is missing a required field (e.g. job family, job level, competency framework), when the agent processes it, then it queries SuccessFactors first and pre-fills the field if a match is found.
  - Given a field cannot be resolved from SuccessFactors, when the agent encounters it, then it asks the user a targeted, single question for that specific field.
  - Given all required fields are resolved, when generation begins, then the agent proceeds without further questions.
- **Maps to Objective:** 4
- **Priority Rank:** 2

**R3: Template-Compliant Profile Draft Generation**
- **Problem to Solve:** Generated content must conform to the specific template governing each job profile, including all sections defined in that template.
- **User Story:** As a job architecture owner, I need the agent to produce a profile that matches the correct template structure and sections, so that the output is immediately usable without reformatting.
- **Acceptance Criteria:**
  - Given a job role and its assigned template, when the agent generates the draft, then all sections defined in that template are populated.
  - Given a template section has prescribed content guidelines, when the agent generates content for that section, then the content conforms to those guidelines.
  - Given content is AI-generated, when the draft is presented, then each section is clearly labelled and sourced for user review.
- **Maps to Objective:** 1
- **Priority Rank:** 3

**R4: Interactive Human Review and Correction Loop**
- **Problem to Solve:** AI-generated content must be validated by a human before being written to the system of record.
- **User Story:** As an HR specialist, I need to review the generated draft and correct any section before the profile is finalised, so that I remain in control of what gets submitted to SuccessFactors.
- **Acceptance Criteria:**
  - Given a draft is generated, when it is presented to the user, then each section is shown clearly with an option to accept or revise.
  - Given a user requests a change to a section, when they provide new input, then the agent regenerates that section and presents the updated draft.
  - Given the user approves the full draft, when they confirm, then the agent proceeds to the selected output mode.
  - Given no explicit approval, when the agent is ready to deliver, then it must request confirmation before proceeding.
- **Maps to Objective:** 1, 3
- **Priority Rank:** 4

**R5: Multiple Output Delivery Modes**
- **Problem to Solve:** Different clients and configurations require different delivery methods; a single output mode would exclude a significant portion of potential users.
- **User Story:** As an HR specialist, I need to choose at runtime whether the agent writes the profile directly to SuccessFactors, exports it as a CSV for bulk import, or delivers it as a formatted document, so that I can use the agent regardless of my system access level or workflow.
- **Acceptance Criteria:**
  - Given a user selects API write, when the profile is approved, then the agent calls the SuccessFactors OData API to create or update the profile and confirms success.
  - Given a user selects CSV export, when the profile is approved, then the agent generates a correctly formatted CSV file conforming to the SuccessFactors Job Profile Builder import schema.
  - Given a user selects document draft, when the profile is approved, then the agent delivers a clean formatted document ready for manual copy-paste or filing.
  - Given an API write fails, when the error is received, then the agent automatically offers the CSV export as a fallback without losing the generated content.
- **Maps to Objective:** 3
- **Priority Rank:** 5

**R6: Batch Profile Generation**
- **Problem to Solve:** Migration projects and large-scale roll-outs require generating hundreds or thousands of profiles without per-profile manual effort.
- **User Story:** As a job architecture owner, I need to provide a list or file of roles and have the agent generate all profiles in a single batch run, so that I can complete a migration without attending to each profile individually.
- **Acceptance Criteria:**
  - Given a user provides a batch input file (e.g. CSV or list of role names), when the agent processes it, then it generates a complete draft for every role in the file.
  - Given a batch run completes, when the summary is presented, then it shows the count of profiles generated, any profiles that required additional input, and any failures.
  - Given a profile in the batch cannot be completed without user input, when the agent encounters it, then it flags it in the summary and continues processing the remainder.
  - Given a batch of any size, when the run executes, then the agent manages API rate limits automatically without failing.
- **Maps to Objective:** 2
- **Priority Rank:** 6

**R7: Content Guardrails and Prompt Injection Protection**
- **Problem to Solve:** AI-generated content must be safe, legally appropriate, and protected from malicious inputs that attempt to manipulate the agent's behaviour.
- **User Story:** As an HR administrator, I need the agent to apply content guardrails so that generated profiles are free of discriminatory, non-compliant, or inappropriate language, and so that the agent cannot be manipulated through crafted inputs.
- **Acceptance Criteria:**
  - Given any generated content, when reviewed by the guardrail layer, then content containing discriminatory language (age, gender, race, disability, etc.) is flagged or removed before presentation to the user.
  - Given a user input that contains a prompt injection attempt, when the agent processes it, then it rejects or neutralises the injection without executing the injected instruction.
  - Given a guardrail violation is detected, when the agent responds, then it explains what was flagged and requests corrected input.
- **Maps to Objective:** 1
- **Priority Rank:** 7

### High-Want Requirements

**R8: SuccessFactors Job Requisition Linkage**
- **Problem to Solve:** Recruiting teams need profiles immediately linked to open requisitions; doing this manually after profile creation adds another step.
- **User Story:** As a hiring manager, I need the agent to optionally attach the newly created job profile to a specific job requisition in SuccessFactors, so that the profile is available to recruiters without a separate manual step.
- **Priority Rank:** 1

**R9: Similarity Search Against Existing Profiles**
- **Problem to Solve:** When creating a new profile, similar existing profiles may provide better starting content than generating from scratch.
- **User Story:** As an HR specialist, I need the agent to suggest and optionally use the most similar existing job profile as a starting point, so that consistent language and structure is preserved across related roles.
- **Priority Rank:** 2

## Non-Functional Requirements

### Performance
- **Latency:** Single profile generation end-to-end (intake to draft) must complete in under 60 seconds for interactive mode.
- **Throughput:** Batch mode must process at least 50 profiles per hour with managed API rate limiting.

### Reliability
- **Availability:** Agent must be available during business hours with graceful degradation if SuccessFactors API is temporarily unavailable.
- **Fallback:** If the API write mode fails, the agent automatically falls back to CSV export without data loss.

### Cost
- **LLM Usage:** Token consumption must be minimised through targeted prompting; batch mode must use efficient prompt batching where possible.

### Explainability
- **Traceability:** Each generated field must be attributable to its source (SuccessFactors lookup, source document, or AI-generated).
- **Decision Logging:** All agent actions — intake, gap resolution, generation, output — are logged at structured milestone level.
- **Uncertainty Communication:** If the agent has low confidence in a generated field, it flags it to the user during review.

## Solution Architecture

**Architecture Overview:**
A Python-based AI agent following the A2A protocol, deployed on SAP BTP. The agent uses an LLM (via SAP Generative AI Hub) for content generation and connects to SAP SuccessFactors via OData APIs for all data reads and writes. No MCP servers are currently available for SuccessFactors APIs; integration is via direct authenticated OData calls.

**Key Components:**

- **Job Profile Builder Agent (Python, A2A):** Core agent — orchestrates intake, gap resolution, generation, review loop, and output delivery
- **SAP Generative AI Hub (LLM):** Powers natural language content generation and document parsing
- **SuccessFactors Generic Objects API** (`sap.sf:apiResource:PLTGenericObjects:v1`): Reads and writes job architecture, templates, and job profiles
- **SuccessFactors Position Management API** (`sap.sf:apiResource:ECPositionManagement:v1`): Provides position context for enrichment
- **SuccessFactors Skills Management API** (`sap.sf:apiResource:ECSkillsManagement:v1`): Provides competency and skills data for profile sections
- **SuccessFactors Job Requisition API** (`sap.sf:apiResource:RCMJobRequisition:v1`): Enables optional linkage of completed profiles to open requisitions

**Integration Points:**

- **SAP SuccessFactors (read):** Job architecture, templates, existing profiles, positions, skills — inbound to agent at gap resolution and generation time
- **SAP SuccessFactors (write):** Completed job profiles — outbound from agent on user approval (API write mode)
- **File I/O:** Batch input files (CSV / list) inbound; CSV bulk-upload export outbound

### Agent Extensibility & Instrumentation

**Agent Extensibility:**
The agent is designed with the following extension points to support future capabilities without requiring a full rebuild:

- **Input handlers:** New source format parsers (e.g. HRIS system integrations, structured XML) can be added as pluggable intake modules
- **Output handlers:** Additional delivery modes (e.g. direct posting to job boards, HRIS systems beyond SuccessFactors) can be added as output plugins
- **Enrichment connectors:** Additional SuccessFactors APIs or external HR content libraries can be added as enrichment sources
- **Content guardrails:** The guardrail layer is configurable — clients can add organisation-specific terminology rules or regulatory checks

**Business Step Instrumentation:**
All key agent steps emit structured log events to enable observability in production. See the Milestones section for log statement definitions. Instrumentation follows the pattern: `[MILESTONE_ID].[achieved|missed]: [description]`.

### Automation & Agent Behaviour

**Automation Level:** Autonomous agent with mandatory human-in-the-loop approval before write actions

**Actions the agent performs without human approval:**
- Read job architecture, templates, positions, and skills data from SuccessFactors
- Parse and interpret source documents and input text
- Generate profile content drafts
- Run batch profile generation and produce batch summary

**Actions that require human review or approval:**
- Writing a completed profile to SuccessFactors via API
- Exporting a completed profile as a CSV file
- Delivering a finalized document draft
- Attaching a profile to a job requisition (if R8 is implemented)

**Model or engine used:** LLM via SAP Generative AI Hub (model selection at deployment time, e.g. GPT-4o or equivalent)

**Knowledge & data sources accessed:**

- **SuccessFactors Job Architecture (Generic Objects API):** Job families, job roles, job codes — read-only, owned by Job Architecture team
- **SuccessFactors Job Profile Templates:** Template definitions and section structures — read-only, owned by HR Configuration team
- **SuccessFactors Existing Job Profiles:** Used for cloning and similarity matching — read-only
- **SuccessFactors Positions:** Position context for enrichment — read-only
- **SuccessFactors Skills & Competencies:** Competency frameworks for profile sections — read-only
- **User-supplied documents:** Word, PDF, CSV files uploaded by the user during session — session-scoped, not persisted

**Tools or connectors invoked:**

- **SuccessFactors Generic Objects API** (read + write): retrieves job architecture, templates, profiles; writes completed profiles — high-risk on write
- **SuccessFactors Position Management API** (read-only): enriches profiles with position data
- **SuccessFactors Skills Management API** (read-only): enriches profiles with competency data
- **SuccessFactors Job Requisition API** (read + optional write): links profiles to requisitions on request
- **Document parser tool** (read-only): extracts content from uploaded Word/PDF files
- **CSV export tool** (write to local file): generates import-ready CSV for bulk upload

**Guardrails & fail-safes:**

- Never write to SuccessFactors without explicit user confirmation — content is always presented for review first
- Never include discriminatory or legally non-compliant language in generated content — guardrail layer scans all output before presentation
- If SuccessFactors API write fails, automatically fall back to CSV export without losing generated content
- If batch processing encounters a profile it cannot complete, it flags it and continues — partial failure does not stop the run
- Prompt injection detection on all user inputs — injected instructions are neutralised before reaching the LLM
- LLM confidence below threshold on any field: flag the field to the user with a note rather than silently presenting low-quality content

## Milestones

### M1: Source Intake

- **Description:** The agent has received source data from the user and identified which job profile fields are present in the input.
- **Achieved when:** Source data is parsed and at least one job profile field is successfully extracted or identified.
- **Log on achievement:** `M1.achieved: source data received and fields identified — source_type={source_type}, fields_found={fields_found}`
- **Log on miss:** `M1.missed: no job profile fields could be identified from the provided input — input_type={input_type}`

### M2: Gap Resolution

- **Description:** All missing required fields have been resolved, either via SuccessFactors lookup or user-provided answers.
- **Achieved when:** All required fields for the target template are populated and the agent is ready to generate.
- **Log on achievement:** `M2.achieved: all required fields resolved — fields_from_sf={fields_from_sf}, fields_from_user={fields_from_user}`
- **Log on miss:** `M2.missed: one or more required fields could not be resolved — missing_fields={missing_fields}`

### M3: Profile Draft Generation

- **Description:** The agent has produced a complete draft job profile conforming to the target template.
- **Achieved when:** All template sections are populated with generated content and the draft is ready for user review.
- **Log on achievement:** `M3.achieved: profile draft generated — template_id={template_id}, sections_populated={sections_populated}`
- **Log on miss:** `M3.missed: profile draft generation failed — template_id={template_id}, reason={reason}`

### M4: Human Review and Approval

- **Description:** The user has reviewed the draft and explicitly approved it for delivery.
- **Achieved when:** User confirms approval of the full draft (with or without corrections applied).
- **Log on achievement:** `M4.achieved: user approved draft — revisions_made={revisions_made}`
- **Log on miss:** `M4.missed: user did not confirm approval — session_status={session_status}`

### M5: Output Delivery

- **Description:** The completed profile has been delivered in the user's selected output mode.
- **Achieved when:** Profile is successfully written to SuccessFactors, exported as CSV, or delivered as a document.
- **Log on achievement:** `M5.achieved: profile delivered — output_mode={output_mode}, profile_id={profile_id}`
- **Log on miss:** `M5.missed: output delivery failed — output_mode={output_mode}, reason={reason}`

### M6: Batch Run Completion

- **Description:** A batch processing run has completed, generating profiles for all roles in the input file.
- **Achieved when:** All roles in the batch have been processed (fully completed or flagged) and a summary is returned.
- **Log on achievement:** `M6.achieved: batch run completed — total_roles={total_roles}, profiles_generated={profiles_generated}, flagged={flagged}`
- **Log on miss:** `M6.missed: batch run did not complete — roles_processed={roles_processed}, reason={reason}`

## Risks, Assumptions, and Dependencies

### Risks

- **SuccessFactors Job Profile Builder API write coverage:** Not all profile sections may be writable via the Generic Objects OData API. The CSV export mode is the designed fallback but the API scope must be validated early in the specification phase.
- **AI content quality for regulated industries:** Generated content must meet equal opportunity and other legal requirements. Content quality depends on the quality of the underlying LLM and the guardrail configuration; a human review step is mandatory to mitigate this.
- **API rate limiting in batch mode:** Large batch runs (10,000+ profiles) may trigger SuccessFactors API throttling. Rate limit management logic is required and must be tested at volume.

### Assumptions (Validate These)

- The client's SuccessFactors instance has the Job Profile Builder module enabled and configured with templates.
- The SuccessFactors Generic Objects API is available in the client's tenant and the agent's service user has appropriate read (and write where applicable) permissions.
- Source documents (Word, PDF) are in reasonably structured formats that a document parser can extract meaningful content from.
- The client's job architecture data in SuccessFactors is sufficiently complete to serve as an enrichment source.

### Dependencies

- SAP SuccessFactors OData API access (Generic Objects, Position, Skills, Job Requisition)
- SAP Generative AI Hub access for LLM inference
- Client-provided SuccessFactors service user credentials with appropriate API permissions
- Confirmed template structures in the client's Job Profile Builder configuration

## Appendix

### Glossary

- **Job Profile Builder:** The SAP SuccessFactors module used to create and manage job profiles, which are structured templates describing a role's responsibilities, qualifications, competencies, and other attributes.
- **Job Architecture:** The hierarchical structure of job families, job functions, job levels, and job codes that governs how roles are classified in SuccessFactors.
- **Template:** A configurable structure in Job Profile Builder that defines which sections a job profile must contain and their content rules.
- **A2A Protocol:** Agent-to-Agent protocol — the communication standard used by the Python-based AI agent for interoperability with other SAP services.
- **Generic Objects API:** The SAP SuccessFactors OData API used to read and write custom object types, including job profile data.
- **Batch Mode:** A mode in which the agent processes a list of roles from a file and generates profiles for all of them in a single unattended run.
